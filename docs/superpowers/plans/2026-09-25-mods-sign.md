# Mods Sign + Dev Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> This plan is being executed inline by its author right after writing it, so each step names the file and
> the behavior it must have instead of repeating the full code. The committed files are the implementation.

**Goal:** Add a "Mods" sign between the no-smoking sign and Exit on the main menu. Clicking it turns the
signpost into a settings page (toggles plus Back) that persists to `config.txt`. Also add a dev harness so the
running game can be driven and tested from the terminal.

**Architecture:** There are two UE4SS Lua mods, loaded straight from `<repo>/mods` via `+ModsFolderPaths`.
`GHPDev` (dev-only) polls `dev/cmd.txt` every 250 ms and writes results to `dev/out.txt`. It supports these commands:
`ping`, `restart <mod>`, `console <cmd>`, `lua <code>`, and `test`. `GolfHeavenPlus` is the shipped mod. It has a
pure `config.lua` that is unit-tested in-game through `test`, and `menu.lua`, which builds signs from the game's
own `WG_MainMenuButton_C` and hooks `CommonButtonBase:HandleButtonClicked`.

**Tech Stack:** UE4SS experimental v3.0.1-1145 (Lua 5.4) and RV There Yet v1.3.20702 (UE 5.6.0). Bash drives
`tools/ghp.sh`.

### Task 3: Mods sign on the main menu

**Files:**
- Create: `mods/GolfHeavenPlus/Scripts/menu.lua`
- Modify: `mods/GolfHeavenPlus/Scripts/main.lua` so it calls `menu.install()`.

Behavior:
- `NotifyOnNewObject(WG_MainMenu_C)` fires when the menu is created. It waits until the menu's `WidgetTree` is built,
  checking again each frame for up to about 2 s, and then runs `setup(menu)` once per menu instance.
- The `newSign(menu, template, text)` helper creates an `Overlay`, a shadow `Image` that copies the template shadow's
  brush, visibility, render transform, and slot, and a `WG_MainMenuButton_C` created through
  `WidgetBlueprintLibrary:Create`. The button gets `DisplayText` and `ButtonWidth` from the template, and the overlay
  copies the template overlay's render transform.
- Insert without `InsertChildAt`: remove the trailing children from the index, add the new sign, re-add them, and
  restore each re-added child's `VerticalBoxSlot` (Size, Padding, H/V alignment).
- Final order: `[settings signs…, NewGame, Load, Join, OnlineSettings, Options, NoSmoking, Mods, Back, Exit]`.
  The settings signs and Back start collapsed.

### Task 4: Settings signpost

**Files:**
- Modify: `mods/GolfHeavenPlus/Scripts/menu.lua`

Behavior:
- Setting signs are `{ key, label }` for `trajectory` ("Trajectory") and `tracer` ("Shot Tracer"), labelled
  `"<label>: On|Off"` and templated on the Online Settings sign, the widest one. Back is templated on Exit.
- A `RegisterHook("/Script/CommonUI.CommonButtonBase:HandleButtonClicked")` pre-hook compares addresses against our
  buttons. Mods switches to the settings view, a setting toggles, saves, and relabels itself, and Back returns
  to the main view.
- The settings view shows only the settings signs, NoSmoking, and Back. The game's sign visibilities are saved before
  collapsing them and restored when leaving.
- The first visible sign gets focus after each switch, so gamepad and keyboard still work.

  settings view in the visibility listing and in a screenshot.
- [ ] **Step 3:** Toggle Trajectory. Expect the label to flip and `config.txt` to contain `trajectory=false`. Click Back
  and expect the original menu. New Game, Load, and Exit stay untouched.
- [ ] **Step 4:** Restart the game. Expect the label to still read `Trajectory: Off`. Toggle it back on.
- [ ] **Step 5:** Commit.
